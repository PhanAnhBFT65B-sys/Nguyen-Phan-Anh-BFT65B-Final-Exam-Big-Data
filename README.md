# A Big-Data Pipeline for Bank-Failure Early Warning (FDIC, 1984Q1–2026Q2)

BFT65B – Big Data Analytics in Finance – Final individual report.
Author: **Nguyễn Phan Anh** (student ID: `11230928`).

This repository rebuilds, from public FDIC data, a reproducible pipeline that
1. downloads 42 years of quarterly Call Reports (1,682,738 bank-quarters), the failure list and the institution table,
2. stores them in a compressed, typed, partitioned Parquet layout (measured against CSV),
3. audits data quality automatically and builds a point-in-time-correct bank-quarter panel with failure labels,
4. processes everything with **Polars** (benchmarked against pandas) and reproduces the key steps in **PySpark**,
5. builds a leak-free feature table and an honestly validated early-warning model (plus a Spark MLlib demo).

No data file is committed: every number in `outputs/` is regenerated by the scripts.

## 3. Key design decisions (details and measurements in the report)

* **Storage.** Raw layer = one zstd Parquet file per quarter (`REPDTE=YYYYMMDD/`), written with an explicit
  Arrow schema → resumable download, no type drift. Clean layer = Hive-partitioned by year.
  Measured: Parquet-zstd is 2.8× smaller than CSV (190 MB vs 527 MB), a full scan is 4× faster and a
  4-column / one-year query is 80× faster (projection + row-group/partition pruning). CSV silently changed
  three column types (e.g. `REPDTE` → integer, `P3ASSET` → string).
* **Data quality.** 30+ automated checks. The most consequential findings: income items are
  year-to-date (de-cumulated to quarterly flows); risk-based capital ratios are encoded as `0` when not
  applicable (before 1990, and for community-bank-leverage-ratio filers since 2020) → converted to missing;
  230 thrifts kept filing after being placed in RTC conservatorship → post-failure rows removed;
  the institution change code marks most failed banks as "mergers" (code 211) → failure vs merger is
  decided from the failure list, never from the change code.
* **Label.** `y(i,q) = 1` if bank *i* fails in (q, q + 4 quarters]; assisted resolutions in the FDIC
  failure list count as failures, mergers do not. Rows after 2025Q2 have incomplete labels and are not used.
* **Processing.** One lazy Polars query (predicate pushdown into the Parquet scan, common sub-expression
  elimination, cheap sorted shifts instead of window group-bys). 2.5× faster than idiomatic pandas on the
  panel build, 3.7× on dynamic features, with 25–33% less memory; outputs identical (checksums, and a
  row-by-row comparison against PySpark).
* **Leakage safeguards.** (1) features use only rows dated ≤ q (explicit backward self-joins, no negative
  shifts) and are verified by recomputing them on data truncated at three cut-off dates; (2) every fitted
  preprocessing step (winsorising limits, medians, scaling) sits inside an sklearn `Pipeline` fitted on training
  folds only; (3) time-ordered validation with a 4-quarter purge; (4) a 4-quarter gap between development
  (1984–2006) and test (2008Q1–2025Q2); (5) model, hyper-parameters and threshold are frozen to
  `outputs/tables/p5_frozen_choices.json` before the single test evaluation.
* **Model.** Baseline logistic regression on 3 ratios vs. regularised logistic vs. histogram gradient boosting.
  Test (558 failing banks): PR-AUC 0.573 (95% bank-bootstrap CI 0.534–0.608) vs 0.527 for the baseline;
  the cost-based threshold flags 2.0% of bank-quarters and catches 94% of failing banks at least once
  before they fail.
